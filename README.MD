Практическая работа №1

## Цель

Выяснить, как программа на C# получает сведения о компьютере, процессе и операционной системе во время выполнения, и чем они отличаются от данных, записанных в коде.

## 1. Информация о компьютере

По результату запуска на скриншоте:

 Имя компьютера: `DESKTOP-PMKJ5GA`.
 Имя пользователя: `PC`.
 Дата и время запуска: `10.10.2026 14:08`.
Эти значения не записаны в коде. Программа получает их во время запуска через .NET и операционную систему. На другом компьютере имя устройства и пользователя будут другими; дата и время также зависят от момента запуска.
## 2. Информация об операционной системе
 `OSVersion`: `Microsoft Windows NT 10.0.19045.0`.
 `Is64BitOperatingSystem`: `True`.
-В программе ОС определяется как 64-разрядная. В окне «Параметры → Система → О системе» нужно сверить строку «Тип системы» и вписать её сюда: **значение на скриншоте не зафиксировано**.
## 3. Логические процессоры

 Гипотеза: 16 логических процессоров.
 Результат программы: 16.
Диспетчер задач -> «Производительность» -> «ЦП» -> «Логические процессоры»: **значение на скриншоте не зафиксировано; сверить на своём компьютере**.
Физические ядра: **значение на скриншоте не зафиксировано; сверить в Диспетчере задач**.
Число логических процессоров не обязано равняться числу физических ядер. Некоторые процессоры благодаря Hyper-Threading/SMT предоставляют ОС несколько логических процессоров на одно физическое ядро.

## 4. Память процесса
 PID процесса на скриншоте мини-монитора: `12320`.
Первый замер `WorkingSet64`: `18 МБ`.
 Замеры 2 и 3: **не видны на скриншоте; повторить запуск и записать их**.
 Показание Диспетчера задач для того же PID: **не зафиксировано; открыть вкладку «Подробности» и сверить PID `12320` во время запуска**.
`WorkingSet64` показывает объём страниц памяти процесса, находящихся в оперативной памяти в момент замера. Показание может меняться. Значение в Диспетчере задач может отличаться, поскольку там может отображаться другая метрика памяти.
## Контрольные вопросы
1. Программа не хранит имя компьютера в коде: она запрашивает его через .NET (класс `Environment`), а .NET получает сведения у операционной системы.
2. ОС управляет доступом программ к процессору, памяти и другим ресурсам, а также предоставляет программам сведения о системе.
3. 64-разрядная ОС поддерживает более широкое адресное пространство, чем 32-разрядная, и может работать с большим объёмом оперативной памяти.
4. `ProcessorCount` показывает число логических процессоров, доступных программе. Оно может отличаться от числа физических ядер.
5. `WorkingSet64` относится к памяти конкретного процесса, находящейся в ОЗУ в момент измерения. Это не вся оперативная память компьютера.
6. Один и тот же код на разных компьютерах даёт разные результаты, потому что отличаются оборудование, ОС, пользователь и состояние процесса.
## Итоговый вывод
Программа получает сведения о компьютере во время работы: обращается к API .NET, которое предоставляет данные операционной системы. Один и тот же исходный код может вывести разные значения на разных компьютерах. В этой работе программа сообщила о 64-разрядной ОС и 16 логических процессорах; первый показанный замер рабочего набора процесса составил 18 МБ.
## Дополнительное задание. Мини-монитор системы
### Что делает программа
Выводит имя компьютера, пользователя, версию и разрядность ОС, число логических процессоров, PID своей программы и три замера рабочего набора памяти процесса.
### Что нового я узнал о классе `Process`
`Process.GetCurrentProcess()` возвращает объект, представляющий текущий процесс. Через него можно получить PID (`Id`) и рабочий набор памяти (`WorkingSet64`). Метод `Refresh()` обновляет сохранённые сведения перед следующим замером.
###Сравнение памяти программы и Диспетчера задач
По приложенному скриншоту программы первый замер составил `18 МБ`. Три замера программы и значение Диспетчера задач для того же PID **не зафиксированы полностью**. Для завершения сравнения нужно повторно запустить мини-монитор, записать все три показания и сравнить их с процессом с тем же PID в Диспетчере задач.
### Почему значение памяти может немного изменяться

Во время работы .NET может выделять и освобождать память, а операционная система управляет размещением страниц процесса в ОЗУ. Поэтому рабочий набор может меняться между измерениями.
